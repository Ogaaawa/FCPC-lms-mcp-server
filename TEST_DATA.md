# Test data for the Moodle MCP server

Every tool currently answers "nothing found" because the test account has no
real data. That is indistinguishable from a tool that is quietly broken. This
document specifies the Moodle content needed to tell the two apart, and the
checks to run once it exists.

Whoever creates this needs permission to create courses and enrol users on
https://lms.fcpc.edu.ph.

---

| Requirement | Why | Who |
|---|---|---|
| A web service token per test account | Nothing can be called without one, and students cannot self-issue on this site | Moodle administrator — see `ADMIN_REQUEST.md` |

| Site timezone set to Philippine time | Deadlines are compared against it | Moodle administrator |

**Without tokens nothing below can be tested.** That is the first blocker.

## Accounts

Three, so that "one user cannot see another user's data" is a real test rather
than an assumption.

| Account | Role | Enrolled in |
|---|---|---|
| `mcp.student1` | Student | Course A and Course B |
| `mcp.student2` | Student | Course B only |
| `mcp.teacher1` | Teacher | Course A |

`mcp.teacher1` is only needed if the teacher-facing tools are built. The
student tools can be verified with the first two.

---

## Course A — "MCP Test Course A"

The main fixture. Every branch of every tool is reachable from it.

### General section

- **Announcements** forum, with two posts:
  - `Exam schedule changed` — body containing an ampersand and a bold word, so
    HTML stripping is exercised
  - `Welcome to the course`

### Week 1 (visible)

| Activity | Type | Setting |
|---|---|---|
| `Essay 1` | Assignment | Due **in 3 days** |
| `Essay 2` | Assignment | Due **in 20 days** |
| `Quiz 1` | Quiz | Closes **in 5 days**, no attempt by student1 |

`Essay 2` sits outside the 14-day default window on purpose: it must appear in
`get_due_assignments(30)` but not in `get_upcoming_deadlines()`.

### Week 2 (visible)

| Activity | Type | Setting |
|---|---|---|
| `Late Report` | Assignment | Due **2 days ago**, nothing submitted |
| `Quiz 2` | Quiz | Attempted and **finished** by student1 |
| `Reading list` | Page or File | No dates |

`Quiz 2` is the negative case: a finished quiz must **not** be reported as
pending. `Reading list` checks that non-graded material still appears in the
course outline.

### Week 3 (**hidden** section)

- `Secret Task` — Assignment, any date

Nothing from this section may appear in any answer.

### Week 4 (visible, **empty**)

No activities. Must be dropped from the course outline rather than printed as
an empty heading.

### One hidden activity

Add `Hidden Quiz` to Week 1 and set its availability to hidden. It must not
appear anywhere.

### Grades

Grade `Essay 1` for `mcp.student1` as **85 / 100**. This makes a course total
exist, which is what `get_my_grades` reports.

## Course B — "MCP Test Course B"

Minimal, to prove that answers combine across courses.

- **Announcements** forum with one post: `Room change`
- One assignment `Task B`, due **in 7 days**
- Both `mcp.student1` and `mcp.student2` enrolled

---

## Messages

From `mcp.teacher1` to `mcp.student1`, two messages, left **unread**:

- `Please see me after class`
- A second message containing an HTML entity, e.g. `Bring your ID & laptop`

Messages are a different inbox from notifications; both need data.

---

## Notifications

These are generated by Moodle, not created by hand. After the fixtures exist:

- Grading `Essay 1` produces an "assignment was graded" notification
- Cron produces a deadline reminder for `Essay 1`

If no notification ever appears, cron is not running. That is a site problem,
not a fault in the server.

## Test matrix

Run these as `mcp.student1` in Claude once the connector is registered. The
expected column is what a correct answer contains.

| # | Tool | Ask | Expect |
|---|---|---|---|
| 1 | `get_my_courses` | "What courses am I in?" | Course A and Course B, with ids |
| 2 | `get_upcoming_deadlines` | "What is coming up?" | `Essay 1`, `Quiz 1`, `Task B`. **Not** `Essay 2` (20 days away) |
| 3 | `get_upcoming_deadlines` | "Anything overdue?" | `Late Report` marked `(overdue)` |
| 4 | `get_due_assignments` | "What assignments are due in 30 days?" | `Essay 1`, `Essay 2`, `Task B` |
| 5 | `get_pending_quizzes` | "Which quizzes do I still need to take?" | `Quiz 1` only. **Not** `Quiz 2` |
| 6 | `get_my_grades` | "How am I doing?" | Course A with a grade near 85; Course B not graded yet |
| 7 | `check_new_messages` | "Any new messages?" | Both messages, sender `mcp.teacher1`, `&` shown as `&`, not `&amp;` |
| 8 | `check_notifications` | "Did I miss anything?" | The grading notification for `Essay 1` |
| 9 | `get_course_announcements` | "Any announcements?" | Posts from both courses |
| 10 | `get_course_announcements` | "What did my teacher post in Course A?" | Only Course A's two posts |
| 11 | `get_course_contents` | "What is in Course A?" | Weeks 1 and 2 with their activities and `Reading list` |
| 12 | `get_course_contents` | (same answer as 11) | **No** `Week 3`, **no** `Secret Task`, **no** `Week 4`, **no** `Hidden Quiz` |

### Isolation

| # | Ask | Expect |
|---|---|---|
| 13 | As `mcp.student2`: "What courses am I in?" | Course B only. Course A must not appear |
| 14 | As `mcp.student2`: "How am I doing?" | No sign of student1's 85 |
| 15 | As `mcp.student1`, after 13-14 | Still sees both courses; nothing has leaked either way |

Run 13 from a **different Claude account**, not a new chat in the same one.

### Teacher tools, if they are built

Requires `mcp.teacher1` and a token for that account.

| # | Ask | Expect |
|---|---|---|
| 16 | "Who has not submitted Essay 1?" | student1 excluded if they submitted; anyone who did not, listed |
| 17 | "How many students are in Course A?" | The enrolment count |
| 18 | "What is the average grade in Course A?" | A figure derived from the grade book |

Before building these, confirm the same calls return **empty** for a student
account and **data** for the teacher account. Moodle answers a permission
failure with an empty list rather than an error, so this comparison is the
only way to know the tool works.

## What is already covered without any of this

`selftest.py` exercises every code path offline with sample data - HTML
stripping, missing fields, hidden sections, overdue flags, empty inboxes, and
user isolation across 20 concurrent requests.

```
python selftest.py
```

What the fixtures add is proof that the **live** Moodle answers as expected.
The two are complementary: selftest catches broken code, fixtures catch wrong
assumptions about Moodle.
